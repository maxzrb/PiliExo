# PiliExo Android 发布流程

本文档适用于 PiliExo Android 正式版本，当前包名为 `com.maxzrb.piliexo`。

## 版本规则

- 测试阶段固定使用当前版本号；修改代码、重打测试包和真机回归时不递增发布序号或 Android `versionCode`。
- 正式标签固定使用 `v[两位年份].[月份].[日期].[当天第几次发布]`，例如 `v26.8.28.1`；前三段必须是正式发布当天的日期，最后一段 `N` 是该日期当天的正式发布次数，从 1 开始。
- 计算下一正式标签时，先读取远端已有 Release 标签：如果当天已有 `vYY.M.D.N`，取当天最大 `N+1`；如果日期变了，标签末段可以重新从 1 开始。例如远端最新为 `v26.8.28.2`，在 2026-08-29 发布时应为 `v26.8.29.1`；同日再次发布才是 `v26.8.29.2`。测试包不占用标签发布编号。
- `pubspec.yaml` 的 `+N` 只表示当天发布序号，用于生成 `vYY.M.D.N` 和应用显示版本；Android 全局递增的安装版本号单独记录在 `android/version.properties`。
- 每次正式 Release 都必须将 `android/version.properties` 中的 `versionCode` 相对上一正式包递增 1，不能随日期或标签末段重置；即使修复一个已经发布的错误版本，也只能继续递增，不能复用较小值。
- 发布版本需要同步更新 `pubspec.yaml`、`version/版本迭代记录.md` 和 `version/release-notes-v<tag>.md`。
- Release Note 每条单独一行，并使用 `[新增]`、`[更改]`、`[修复]`、`[同步]` 前缀；`[同步]` 专门记录后续不定期同步的 PiliPlus 上游改动。
- 已发布版本若仅补充低风险的更新交互修复，且明确要求覆盖现有版本，可保持同一标签的发布序号和 Android `versionCode` 不变，重新构建同名资产并替换 GitHub/ModelScope 文件；这不算创建新的 Release。只要创建新标签，就必须按全局规则递增 Android `versionCode`。

### 测试构建的版本约束

- 测试包始终复用当前远端正式 Release 的发布版本号；本次发布完成后当前远端正式版本为 `v26.8.30.2`，测试构建保持 `26.8.30+2`，不因修复、重打包或真机回归递增 Android `versionCode`。
- 历史 `v26.8.28.3` APK 只属于测试产物，不得当作正式版本或下一次发布依据；下一次正式发布仍须按发布日期和当天构建次数重新计算。
- 如果应用显示 `SNAPSHOT+1` 或提示 Release 标签格式不受支持，先检查 `pili_release.json`、`--dart-define-from-file` 和本机 `android/local.properties` 中的 `flutter.versionName` 是否为旧值；`flutter.versionCode` 不作为正式 Android 版本号来源，Gradle 会优先读取仓库内的 `android/version.properties`。
- `android/local.properties` 是本机生成文件，不能作为 Android 全局版本号的记录；如需临时验证，可使用 `-Ppili.androidVersionCode` 显式覆盖，正式构建必须更新并提交 `android/version.properties`。

## 发布前准备

1. 确认工作树、上游同步状态和目标版本，检查是否误带入本地测试文件；保留 Android HDR、SurfaceView、回退和 ABI 更新逻辑。
2. 校验 Flutter 工具链版本，确保 `.fvmrc`、`pubspec.yaml`、`pubspec.lock` 和实际 SDK 都是 `3.47.2`；跨盘构建问题由工程默认配置处理，不要临时改版本约束或删除锁文件。
3. 发布时才修改 `pubspec.yaml` 的版本号，例如：

   ```powershell
   # 例：远端最新 Release 为 v26.8.28.2，发布日期为 2026-08-29
   # 本次直接编辑 pubspec.yaml 为 26.8.29+1，对应标签 v26.8.29.1
   # 同时将 android/version.properties 的 versionCode 更新为上一正式包 + 1
   ```

   正式发布前同步更新 `android/version.properties`，将 `versionCode` 设置为上一正式包的 Android `versionCode + 1`；不能把当天标签的末段直接写入该字段。

4. 完成版本记录和 Release Note，确认包名仍为 `com.maxzrb.piliexo`，不要改回原版包名。
5. 配置正式签名：`android/key.properties` 不进入仓库；正式包必须使用与上一正式版本相同的签名密钥，否则 Android 无法覆盖更新。首次生成本项目正式密钥时使用以下命令并按提示输入密码，生成后将 `android/key.properties.example` 复制为 `android/key.properties` 并填写实际密码：

   ```powershell
   keytool -genkeypair -v `
     -keystore android/piliexo-release.jks `
     -storetype PKCS12 -alias piliexo -keyalg RSA -keysize 4096 -validity 10000
   Copy-Item android/key.properties.example android/key.properties
   ```

   `android/piliexo-release.jks`、`android/key.properties` 和密码必须单独备份，不能提交到仓库或上传到 Release。若此前正式包误用 Debug 签名，切换到正式密钥的第一个包无法覆盖旧包，用户需要卸载旧包后安装一次；之后必须一直使用同一正式密钥。

## 自动生成发布元数据

在项目根目录执行：

```powershell
.\lib\scripts\build.ps1
```

脚本会从 `pubspec.yaml` 读取版本，并从 `android/version.properties` 读取全局递增的 Android `versionCode`，生成本地忽略文件 `pili_release.json`。该文件同时包含版本名、Android `versionCode`、标签发布序号 `releaseBuild`、构建时间和 Git 提交哈希，必须在构建前生成，不能手工长期复用旧版本元数据。

Android HDR 播放依赖仓库内的 `android/app/libs/media3-decoder-ffmpeg-1.11.0-ac3-eac3-truehd.aar`。它只包含 `arm64-v8a` 和 `armeabi-v7a`，优先使用设备硬件解码器，硬件不支持时为 AC-3、E-AC-3/E-AC-3-JOC 和 Dolby TrueHD 提供 FFmpeg 软件回退；更新 Media3 或 FFmpeg 时必须重新构建并核验该 AAR，不能只删除本地依赖。

## 固定 Flutter 工具链与跨盘构建

- 项目统一使用 Flutter `3.47.2`：`.fvmrc`、`pubspec.yaml` 和 `pubspec.lock` 必须保持一致。Flutter `3.47.1` 不能替代 `3.47.2`，否则 `flutter pub get` 会因 SDK 约束不匹配失败。
- 构建前执行工具链校验：

  ```powershell
  & .\lib\scripts\verify_flutter.ps1 -FlutterPath 'C:\path\to\flutter-3.47.2\bin\flutter.bat'
  ```

  如果 `flutter` 已在 `PATH` 中，可以省略 `-FlutterPath`。校验脚本会检查 `.fvmrc`、`pubspec.yaml`、`pubspec.lock` 和实际 `flutter --version`，避免错误 SDK 进入发布流程。
- `android/gradle.properties` 已固定 `kotlin.incremental=false`。因为项目构建目录位于 D 盘、部分 Flutter 插件源码/缓存位于 C 盘，Kotlin 增量缓存无法计算跨盘相对路径；现在本地和 CI 默认都使用非增量 Kotlin 编译，无需手工追加 `-Pkotlin.incremental=false`。
- Android 工程保留 `android.builtInKotlin=false` 和 `android.newDsl=false` 兼容开关：当前 Flutter Gradle 插件与 AGP 9 新 DSL 组合会触发 `ApplicationExtension` / `AbstractAppExtension` 类型冲突，不能直接删除；`android.enableJetifier=true` 也暂保留以兼容现有 Android 依赖。跨盘问题由 `kotlin.incremental=false` 单独解决。

## 检查与构建

```powershell
$flutter = 'C:\path\to\flutter-3.47.2\bin\flutter.bat'
& .\lib\scripts\verify_flutter.ps1 -FlutterPath $flutter
& $flutter pub get
& $flutter test --no-pub
& $flutter analyze --no-pub --no-fatal-infos
```

Android 正式包只构建手机 ARM 架构：

```powershell
& $flutter build apk --release --split-per-abi `
  --target-platform android-arm,android-arm64 `
  --dart-define-from-file=pili_release.json --no-pub
```

产物应重命名为：

```text
PiliExo_android_vYY.M.D.N_arm64-v8a.apk
PiliExo_android_vYY.M.D.N_armeabi-v7a.apk
```

发布前用 `aapt dump badging` 检查：

- `name='com.maxzrb.piliexo'`；
- `versionName` 与发布标签日期部分一致；
- `versionCode` 和上一正式版本的 Android versionCode 为全局 N+1 关系，与标签末段无关；
- arm64 包只包含 `arm64-v8a`，v7a 包只包含 `armeabi-v7a`；
- 两个 ABI 包都必须包含 `libffmpegJNI.so`，且 release 映射中保留 `androidx.media3.decoder.ffmpeg.FfmpegAudioRenderer`；
- Release 使用正式签名，不得使用 debug keystore。

随后计算 SHA-256，记录到 `docs/codex/STATUS.md` 和 `version/工作进度.md`，并运行：

```powershell
git diff --check
& $flutter test --no-pub
```

## 发布与镜像

1. 提交代码并推送分支；确认 CI 的 Android 构建同样只生成 arm64-v8a 和 armeabi-v7a。
2. 在 `maxzrb/PiliExo` 创建与版本号完全一致的 GitHub Release，例如 `v26.8.29.1`。
3. 上传两个 ABI APK，资产名必须与更新器和 ModelScope 镜像路径完全一致。
4. 将相同文件上传到 ModelScope 数据集 `AerithDream/PiliExo` 的：

   ```text
   releases/vYY.M.D.N/PiliExo_android_vYY.M.D.N_arm64-v8a.apk
   releases/vYY.M.D.N/PiliExo_android_vYY.M.D.N_armeabi-v7a.apk
   ```

5. 用浏览器或 `HEAD` 请求验证两个 ModelScope 地址可访问，并比对镜像与 GitHub 资产 SHA-256。
6. 更新器会读取 GitHub Release 标签判断新版本，在 Android 上按 `supportedAbis` 选择精确 APK；ModelScope 不可达时才使用 GitHub Release 下载地址。

## 发布后验收

- 从上一正式版本检查更新，确认标签比较、ModelScope 优先和 GitHub 兜底均正常。
- 在 arm64 设备验收 HDR10、Dolby Vision、HDR Vivid、SurfaceView 清屏、画质切换、字幕、弹幕、横竖屏、前后台和画中画。
- 验收默认震动开启、强度 80、滑块即时反馈，以及磨砂开关和轻薄/标准/浓厚三档效果。
- 确认原版 PiliPlus 与 PiliExo 可以共存，升级 PiliExo 不影响原版数据和设置。
- 确认不支持 Dolby 音频硬解的设备仍能通过 FFmpeg 软件回退出声；E-AC-3-JOC 软件路径只保证 PCM 出声，不承诺保留 Dolby Atmos 对象直通。
- 发布完成后将提交、标签、资产地址、哈希、已知限制和后续 `[同步]` 事项写入 HandShake 状态记录。
