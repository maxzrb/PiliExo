## 方法

显式诊断构建以 40 ms 采样；每组正常 3 秒、3 倍 3 秒、恢复 1 倍 3 秒，两轮。统计每个切速标记后最初 2 秒，保留最初瞬间。逐组读取 current-ao 和参数，不能只按请求值给结果命名。先前 20 ms/debugPrint 节流日志只保留完整窗口，不把未完成末轮算作验收。

下表为 mpv 输出掉帧增量，不是屏幕实测 FPS；各格为两轮结果。decoder-frame-drop-count 均未增加。素材各组顺序播放，非严格相同片段的随机交叉实验；AudioTrack 回测作为顺序漂移对照。两轮不足以代表长时间稳定性。

进一步的滤镜对照完整采集 5424 个样本：AudioTrack 常驻 scaletempo2、0/50/200 ms 通用缓冲、缩短滤镜窗口、强制 48 kHz 都没有解决退出时的大量掉帧。关闭音调校正的纯诊断对照也仍有 69 / 68 帧退出丢弃，且不符合用户音调要求，明确排除。OpenSL ES 20 ms + 常驻 scaletempo2 四个边沿均为 0，但没有足够证据支持额外常驻滤镜，候选保留 mpv 默认音调校正路径。AAudio 常驻滤镜仍有一次 5 帧退出丢弃。

AudioTrack 补充 PCM16 对照：50 ms 时退出 57 / 58 帧；PCM16 + 48 kHz 时 58 / 57 帧；通用缓冲 0 时 65 / 65 帧。未修复，不把这些调参写入正式路径。

## 录屏复核

另录制约 80 秒屏幕，三条输出各两轮，音调校正均为 yes。录屏分辨率 632×1368；只分析视频下部 500×120 区域，避开 HUD、弹幕主区域与系统时钟；降采样灰度 160×60，相邻画面平均差小于 0.6/255 作为近似重复的候选。该启发式用于发现长停画，不能等同高帧率摄像机、真实面板扫描或声音延迟测量。录屏与设备时钟只做启动前时间对齐，未补偿启动延迟。

- AudioTrack 200 ms：切入窗口近似停画 371 / 350 ms，切出窗口 76 / 98 ms；退出输出丢弃 83 / 82，播放时钟单步约 617 / 633 ms。
- OpenSL ES 20 ms：切入/退出窗口近似重复区间最大约 11～12 ms；退出输出丢弃 3 / 0，播放时钟最大单步约 150 ms。说明显著改善，但录屏负载下仍有残留，不能宣称所有场景零丢帧。
- AAudio low-latency 50 ms：相同指标约 11～22 ms；退出输出丢弃 0 / 1，另一次切入 2 帧。

video-pts 在本机 mpv 不可用，time-pos 仅用作播放时钟指标，不把其推进当物理视频呈现。AudioTrack 与候选差异同时出现在输出计数、时钟和录屏，支持进一步验证低缓冲路线。

## 机制线索

mpv 官方文档说明较大的音频缓冲会降低控制响应。其播放音频时钟由写入 PTS 减去当前 audio_speed 与输出延迟的乘积计算。切速时已有队列与新速度的对应关系，可能解释本机的时钟跳变和视频等待/追赶；这是与对照结果一致的机制推断，尚非完成的 native 根因修复。
