# PiliExo 本机发布工具链

本文件记录本机用于编译和发布的持久化工具链位置。工具链和编译产物不得放入项目 `tmp/`，避免被环境自动清理。

## Flutter SDK（当前：3.47.5）

- 版本：`3.47.5` stable（对应 `.fvmrc`）。
- 持久路径：项目内 `tools/flutter-3.47.5/flutter`；压缩包在 `tools/flutter-3.47.5/flutter_windows_3.47.5-stable.zip`，两者均被 Git 忽略，不放入会被清理的 `build/`。
- 压缩包 SHA-256：`0ccd71931f49c2fbe394b1eeb6d79af3d624058a043ea0d03d34160581624fb8`（Flutter 官方发布清单）；Dart 为 `3.13.4`，engine revision 为 `af7e796e161ae0bb1ff0758c71a7105418bd9ded`。
- framework 已逐项应用项目 Android 补丁 24 个；项目内 `tools/pub-cache/` 的 `material_ui 1.4.0` 已应用 9 个 material 补丁。`tabs.patch` 对齐上游 1.4.0，`scaffold.patch` 适配该版本将 BottomSheet 默认值移入 generated part 的源码布局。补丁脚本会先将补丁文件换行统一为 LF。
- 因项目绝对路径含空格，`objective_c` 原生资源 hook 在该路径下会将命令截断；测试和 Android 构建使用 `subst P:` 映射同一个项目目录，并在映射路径下执行。`P:` 不是第二份源码，也不应提交；重启后需要重新映射。
- 项目版本源仍以 `.fvmrc`、`pubspec.yaml`、`pubspec.lock` 和 `lib/scripts/verify_flutter.ps1` 为准。

PowerShell 发布前设置：

```powershell
$projectRoot = (Resolve-Path .).Path
subst P: $projectRoot
Set-Location P:\
$env:FLUTTER_ROOT = 'P:\tools\flutter-3.47.5\flutter'
$env:PUB_CACHE = 'P:\tools\pub-cache'
$env:FLUTTER_STORAGE_BASE_URL = 'https://storage.flutter-io.cn'
$flutter = Join-Path $env:FLUTTER_ROOT 'bin\flutter.bat'
$env:Path = "$(Split-Path $flutter);$env:Path"
& .\lib\scripts\verify_flutter.ps1 -FlutterPath $flutter
```

## 持久化发布产物

正式 APK 和校验记录统一放在项目内的 `dist/release/<releaseTag>/`，例如：

```text
dist/release/v26.8.30.6/
├── PiliExo_android_v26.8.30.6_arm64-v8a.apk
├── PiliExo_android_v26.8.30.6_armeabi-v7a.apk
└── SHA256SUMS.txt
```

`dist/` 已被 Git 忽略，产物保留在持久目录但不会进入源码提交。正式签名文件仍只保留在 `android/piliexo-release.jks` 和 `android/key.properties`，两者均不得提交或上传。
