# 视频下采样 ADB 真机核验

时间：2026-11-10 10:32–10:40（Asia/Shanghai）。

## 结论

- ExoPlayer（Media3）：本机实播的 4K HDR 视频以独立 SurfaceView 输出，SurfaceFlinger 标记为 DEVICE 合成；高通 Composer dump 的视频层使用 SDE/DPU 管线缩小。没有暴露滤波核名称，不能据此认定是双线性、双三次或 Lanczos。
- mpv：本机实播存在 3840×2160 的 SurfaceTexture，SurfaceFlinger 接收屏幕尺寸的 Flutter 图层，视频缩小发生在 Flutter 图层内部。结合对应源码的 SimpleVideo 默认 FilterQuality.low，可判断这一阶段配置为双线性。mpv 自身另有 dscale=bilinear，但本次没有通过 ADB 直接读取该属性。
- 真机核验支持此前关于两种渲染路径的判断；没有完成滤波核的黑盒识别或像素级频率响应测量。

## 采集命令与参考输出

使用真实应用和固定片源，不制作独立测试应用。以下按输入样例、参考输出和实际结果记录；这是 ADB 诊断记录，不是声称执行过 FFmpeg FATE 套件。

### 样例1：确认 Media3 输出和缩小位置

输入：应用内播放器洞察报告 Media3 原生 HDR，播放上述片源，竖屏半屏状态执行：

```text
adb shell dumpsys SurfaceFlinger
```

参考字段：视频层的 sourceCrop 保持片源尺寸，displayFrame 小于片源尺寸；视频层的 hwc composition 指出系统合成方式。

实际输出摘录（同一 Output Layer）：

```text
sourceCrop=[0.000000 0.000000 3840.000000 2160.000000]
displayFrame=[0 138 1263 848]
dataspace=BT2020_ITU_PQ
hwc: layer=0x085884 composition=DEVICE (2)
```

实际视频显示区域是 1263×710。底层分配的 3840×2176 缓冲包含对齐填充，有效视频裁剪仍是 3840×2160。

追加横屏布局采样的 Composer 输入：

```text
adb shell dumpsys android.hardware.graphics.composer3.IComposer/default
```

实际视频层格式为 Y_CBCR_420_TP10_UBWC，管线表为 Comp Type=SDE，分成 Rot-inl-1 / Rot-inl-2 两条管线。有效源区域合计 3840×2160，旋转后送入物理屏幕目标区域。没有 bilinear、Lanczos 或可命名的滤波核字段。

结果：确认硬件显示管线负责本次 Media3 视频缩小；滤波核名称未知。

### 样例2：确认 mpv 的纹理尺寸和最终合成位置

输入：同一片源切换为 mpv，洞察报告 mpv 兼容播放器，超分辨率禁用；播放状态下执行：

```text
adb shell dumpsys gfxinfo com.maxzrb.piliexo
adb shell dumpsys SurfaceFlinger
```

参考字段：若 mpv 保留视频原尺寸纹理，gfxinfo 应存在 3840×2160 的 SurfaceTexture；如果最终缩小在 Flutter 内完成，SurfaceFlinger 不应再以独立活动 4K 视频层缩到播放区域。

实际 gfxinfo 输出摘录：

```text
32400.00 KiB | 3840 (3840) x 2160 | ... | SurfaceTexture-0-22033-1
```

竖屏、横屏采样均能读到上述 4K SurfaceTexture。SurfaceFlinger 活动视频显示通过 Flutter SurfaceView 图层，sourceCrop 为屏幕尺寸 1264×2736，与 displayFrame 尺寸一致，没有活动独立 4K 视频层的缩小操作。dump 的历史 gralloc 列表仍保留旧 Media3 缓冲，不能把历史分配当作活动视频层。

结果：确认 mpv 先输出 4K 纹理，最终视频尺寸适配在 Flutter 图层内部完成。最后屏幕仍通过 DEVICE 合成，不能把这个 DEVICE 标记误解为视频也在 DPU 内从4K缩小。

### 样例3：运行时属性可读性

输入：

```text
adb shell run-as com.maxzrb.piliexo id
```

实际输出：

```text
run-as: package not debuggable: com.maxzrb.piliexo
```

结果：正式包不能通过 run-as 进入进程权限环境。本次没有注入、重新打包、root 或新增 IPC，未读取 mpv 运行时 dscale，也未读取实际 GPU sampler 状态。双线性结论仍有源码配置依据，不把它表述成 ADB 对滤波核的独立测量。
