# 发布事故与防回归清单（2026-11-11）

## P0：v26.11.11.1 覆盖包卡在启动页

现象：应用进程存活，没有应用崩溃和 ANR，系统 Splash 一直不消失。重启设备无法恢复；换回 261110+3 完整内容可正常启动。

定位过程：

1. 正常包日志出现 `media_kit` 插件已注册和 Flutter 引擎预热；故障包没有插件注册日志。
2. 将故障包 `classes.dex` 单独放进正常包后立即复现，确认问题在 Android DEX 层。
3. DEX 静态检查发现缺少 `io.flutter.plugins.GeneratedPluginRegistrant`。
4. 缺少注册类使 MediaKit Android helper 没有初始化 JavaVM，Dart 侧 `MediaKit.ensureInitialized()` 的等待循环永久阻塞，因此 Flutter 首帧没有提交。

根因：隔离构建通过 `git archive` 创建源码树时，遗漏了被 `.gitignore` 排除但构建实际依赖的 `android/app/src/main/java/io/flutter/plugins/GeneratedPluginRegistrant.java`。

修复：强制跟踪该生成文件；构建后检查最终 DEX 包含注册类；arm64 真机冷启动约 233ms，首页和 MediaKit 初始化正常。

## P1：更新检查误报标签格式错误

原逻辑把 HTTP 错误返回的 `message` Map、空响应和真正的非法标签都归到“Release 标签格式不受支持”。现已区分网络异常、403/429 限流、其他 HTTP 状态、响应缺字段和真实非法标签，并保留实际非法标签供排查。

## P1：同版本覆盖包的源码追溯风险

覆盖包必须重新生成发布元数据，使 AOT 内嵌提交等于最终修复提交。只检查版本号和 APK 签名不足以证明源码一致。本次最终 AOT 提交为 `ead9c3ec71ecce94304cc91f75a09eb5b35e042b`，发布标签仍固定原标注提交，不移动标签。

## P1：用户设置不能直接变成产品默认值

从用户导出设置制作默认值时只允许公开偏好。以下内容永久排除：

- `buvid`、Cookie、登录凭证、用户与设备标识。
- WebDAV URI、用户名、密码和目录。
- 设备显示模式及屏幕宽高派生值。
- 任何令牌、密钥、服务器地址或含个人信息的自由文本。

默认项只在键缺失时写入，不覆盖已有用户选择。设置文件导出和 WebDAV 快照统一调用 `GStorage.exportAllSettings()`，并在导出前补齐默认项，保证新设置可恢复。

## 动态 HDR 既有回归

此前审查已记录并修复 FFmpeg 私有参数传递、seek 空载荷清理、切源会话复用、长度前缀解析和迟到 JNI 回调释放问题。完整说明见 `docs/近期构建审查与修复-2026-11-11.md`。修改播放器核心时必须重新运行固定输入与参考输出，不得只验证“能编译”。

## 发布门禁

每次 Android 发布按顺序执行：

```text
lib/scripts/verify_android_plugins.ps1
flutter test
flutter analyze
flutter build apk --release --split-per-abi ...
tool/verify_release_apk.py <arm64.apk> <v7.apk> --source-commit <commit> --version <version>
apksigner verify --print-certs <apk>
zipalign -c -P 16 4 <apk>
adb install --no-streaming -r <arm64.apk>
adb shell am start -W -n com.maxzrb.piliexo/.MainActivity
```

冷启动必须显示可用页面且进程存活。无设备时必须标成“未完成设备验收”，不能以静态检查或日志无崩溃代替。
